1. Executive Summary & The Core Research Problem

ReAssist is an autonomous, cost-governed research intelligence engine engineered to accelerate academic and industrial R&D. The engine automates the end-to-end scientific research lifecycle: ingesting peer-reviewed academic papers from arXiv, Semantic Scholar, and proprietary PDF document stores; synthesizing cross-paper paradigms; systematically detecting unaddressed literature blind spots; formulating mathematically formal research hypotheses; and outputting concrete engineering execution plans.

The Fundamental Architectural Question
"When is a multi-agent system actually worth its cost and latency compared to a single LLM or Chain-of-Thought (CoT) baseline?"
Most contemporary agent swarms suffer from economic irresponsibility: burning 5 to 10 sequential LLM completions for simple informational lookups. ReAssist was engineered around the thesis that multi-agent systems only provide tangible ROI on complex, exploratory research queries. For all other queries, a single prompt is 4x faster and 4x cheaper. ReAssist resolves this through an AgenticOps Router that enforces programmatic cost control while maintaining frontier reasoning capability when required.

2. Architectural Rationale: Why This Particular Approach?

2.1 Multi-Agent Task Decomposition vs. Monolithic Prompts

When a single prompt is tasked with simultaneously digesting 5 academic papers, extracting methodology, discovering contradictions, identifying literature gaps, generating novel ideas, and estimating timelines, it suffers from severe attention dispersion and the empirical "Lost in the Middle" phenomenon. Important empirical details from interior papers are forgotten, and outputs gravitate toward superficial generalities.

ReAssist enforces the Single Responsibility Principle (SRP): 7 distinct intelligence agents handle discrete analytical objectives. For example, GapFinderAgent does not attempt to solve problems; it strictly isolates limitations and unaddressed edges. TechniqueAgent focuses exclusively on mathematical frameworks and benchmark datasets.

2.2 Declarative LangGraph State Machine vs. Imperative Scripts

Early implementations relied on procedural Python scripts with manual retry loops and nested if/else statements. This led to brittle error handling, race conditions, and an inability to manage complex cyclical flows. ReAssist migrated to a LangGraph declarative state graph (src/pipeline/graph_builder.py):

  • Strongly Typed State: An immutable-by-contract PipelineState typed dictionary flows through all nodes.
  • Native Cyclical Feedback Loops: Enables Self-RAG and Corrective RAG (CRAG) loops without recursive stack overhead.
  • Isolated State Mutations: Nodes return partial dictionary diffs, preventing unintended state overwrites.

2.3 Context Slicing (required_inputs)

Passing cumulative execution history to all cascading agents creates $O(N^2)$ token explosion. ReAssist implements strict Context Slicing: each agent specifies a required_inputs manifest. For example, GapFinderAgent receives only the synthesized text; IdeaGeneratorAgent receives only synthesis and gaps. This reduced cumulative token consumption by 52% across the 7 core stages.

4. Technical Obstacles Encountered & Engineering Mitigations

Obstacle Faced Root Cause & Failure Mode Engineering Mitigation Implemented
1. Hallucination Cascades In sequential chains, an ungrounded inference by an early agent is accepted as fact downstream, multiplying errors. Engineered AnswerVerifier at pipeline termination. Operates at temperature=0.0 to audit claims against raw source abstracts.
2. Retrieval Drift & Low Relevance arXiv keyword queries frequently return off-topic papers for niche queries, corrupting downstream synthesis. Implemented Corrective RAG (CRAG): RelevanceGrader filters irrelevant papers; QueryRewriter rewrites queries up to 2 times; triggers Tavily web fallback.
3. Token Bloat & Exponential Costs Accumulating raw text and chat history caused prompt tokens to exceed limits and incur quadratic costs. Enforced Context Slicing via required_inputs, capped summarizer chunks at 2000 tokens, and deployed 3-tier model dispatch.
4. Client HTTP Timeouts A 35-second multi-agent pipeline execution exceeded browser HTTP connection and proxy timeout thresholds. Architected an asynchronous job queue in FastAPI (/analyze returns job_id), with client polling and SQLite WAL persistence.
5. Cloud API Lock-in Relying exclusively on proprietary cloud APIs created high costs and vendor vulnerability. Engineered a unified provider abstraction supporting OpenAI, AWS Bedrock, local Ollama (Llama 3.1 / Phi-3), and Hugging Face.

5. End-to-End Operational Lifecycle & Workflow

The ReAssist engine executes through 12 deterministic stages organized into three distinct operational rings: Ingestion & Routing, Corrective Verification & Search, and Deep Intelligence & Synthesis.

Figure 3: Self-Corrective RAG (CRAG) Feedback Loop Topology

Detailed 12-Stage Execution Breakdown

  1. Phase 1: Ingestion & Telemetry Initialization: User submits research query or PDF via Next.js; FastAPI registers background task and assigns unique trace ID.
  2. Phase 2: AgenticOps Complexity Scoring: Lexical analyzer evaluates complexity (jargon, word count, comparisons) and precision (recency, survey intent). Routes to CoT if score ≤ 4; triggers Multi-Agent if ≥ 5.
  3. Phase 3: Academic Literature Discovery: SearchAgent queries arXiv and Semantic Scholar. In PDF mode, RAGRetrieverAgent extracts vector chunks from ChromaDB.
  4. Phase 4: Binary Relevance Grading: RelevanceGrader classifies paper abstracts as relevant or irrelevant against user intent. Irrelevant papers are pruned.
  5. Phase 5: Self-Corrective Query Rewriting: If verified papers < 2, QueryRewriter rewrites the search query and retries (max 2 rewrites). If still failing, triggers Tavily web search fallback.
  6. Phase 6: Chunked Literature Summarization: SummarizerAgent summarizes verified papers in 2,000-token blocks, extracting methods and empirical metrics.
  7. Phase 7: Cross-Paper Knowledge Synthesis: SynthesizerAgent clusters shared paradigms, conflicting findings, and historical progress.
  8. Phase 8: Research Gap Identification: GapFinderAgent isolates open frontiers, unexplored parameter spaces, and benchmark voids.
  9. Phase 9: Novel Idea Generation: IdeaGeneratorAgent outputs formal hypotheses, mathematical formulation, and experimental procedures.
  10. Phase 10: Technique & Framework Mapping: TechniqueAgent specifies baseline models, evaluation metrics, and open-source datasets.
  11. Phase 11: Implementation Guidance: GuidanceAgent estimates difficulty, prerequisite skills, compute requirements, and milestone timelines.
  12. Phase 12: Answer Verification & Rendering: AnswerVerifier audits synthesis against source papers; results are saved to database and rendered in Next.js UI.

6. In-Depth Technology Stack Breakdown

6.1 Vector RAG (Retrieval-Augmented Generation) Architecture

  • Document Processing (document_processor.py): Uses RecursiveCharacterTextSplitter with chunk_size=1000 and chunk_overlap=150, ensuring semantic continuity across chunk edges.
  • Embeddings Abstraction (embeddings.py): Pluggable embeddings supporting OpenAI text-embedding-ada-002, AWS Bedrock Amazon Titan v2, local Ollama nomic-embed-text, and Hugging Face BAAI/bge-large-en-v1.5.
  • ChromaDB Vector Store (retriever.py): Uses persistent HNSW indexing with Cosine distance. Workspaces have isolated collections (ws_{workspace_id}).
  • Corrective RAG (CRAG): Dynamically grades retrieved chunks and triggers query rewrites or web search fallback if vector similarity is weak.

6.2 Dynamic Model Tiering

  • Tier 1 (Fast & Economical): gpt-4o-mini / Claude Haiku / local Phi-3 for binary relevance grading, query rewriting, and verification.
  • Tier 2 (Balanced): gpt-4o-mini / Claude Sonnet for paper summarization and implementation roadmaps.
  • Tier 3 (Frontier Reasoning): gpt-4o / Claude 3.5 Sonnet exclusively for literature synthesis, contradiction resolution, and hypothesis formulation.

7. Project Defense & Viva Voce Q&A Cheat Sheet

Q1: Why not just use ChatGPT or Claude directly with a single prompt?
A: Monolithic prompts suffer from attention dilution ("Lost in the Middle") when ingesting multiple papers. They produce vague, generic summaries. By decomposing the workflow into 7 focused agents, ReAssist achieves +56% higher specificity in hypotheses and +112% higher actionability in implementation roadmaps.
Q2: Multi-agent systems are slow and expensive. How do you justify this in production?
A: That is why we built the AgenticOps Router. We do not run the multi-agent pipeline for every query. Simple queries are automatically routed to a single-prompt CoT baseline (9s, $0.0015). The multi-agent pipeline is reserved for complex, novel queries, delivering an overall 75% cost reduction.
Q3: How do you prevent hallucination propagation across cascading agents?
A: We apply two independent guardrails: (1) RelevanceGrader filters out irrelevant papers before synthesis begins, and (2) AnswerVerifier audits the final synthesis against source abstracts at temperature=0.0, explicitly flagging unbacked claims.
Q4: Why LangGraph instead of open-ended frameworks like AutoGen or CrewAI?
A: AutoGen and CrewAI rely on conversational agent loops that are non-deterministic, hard to debug, and token-expensive. LangGraph provides a declarative, typed state machine where state transitions, conditional loops (CRAG), and error recovery are strictly defined and auditable.
Q5: How does your vector RAG differ from standard Naive RAG?
A: Standard naive RAG blindly trusts whatever vector chunks the database returns. ReAssist applies Corrective RAG (CRAG): the RelevanceGrader verifies chunk relevance, and if chunks fail similarity thresholds, triggers query rewrites or web search fallbacks.
Q6: What happens if arXiv or the LLM provider rate-limits your pipeline?
A: The orchestrator wraps every node with _run_with_retry using exponential backoff (sleeping 2^attempt * 5 seconds on RateLimitError), and the FastAPI backend decouples the UI from execution via an asynchronous polling job queue.
