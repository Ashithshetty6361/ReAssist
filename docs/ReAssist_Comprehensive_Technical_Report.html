1. Executive Summary & The Core Research Problem

ReAssist is an autonomous research intelligence engine engineered to accelerate scientific discovery. The system automates the literature exploration cycle: retrieving peer-reviewed literature across academic repositories (arXiv, Semantic Scholar) and local vector databases (ChromaDB), synthesizing findings across disparate works, systematically pinpointing unexplored research gaps, formulating novel mathematical hypotheses, and designing concrete engineering implementation roadmaps.

Generative AI systems typically fall victim to two operational extremes: (1) Monolithic single-prompt queries that suffer from context saturation, attention dispersion, and superficial summaries, or (2) Unconstrained multi-agent swarms that trigger dozens of uncoordinated LLM calls, generating excessive token costs and 40+ second latencies.

The Fundamental Research Question
"When is a multi-agent system actually worth its cost and latency compared to a single LLM or Chain-of-Thought (CoT) baseline?"
ReAssist addresses this by introducing an AgenticOps heuristic router that dynamically classifies incoming queries, reducing operational costs by ~75% while delivering +56% higher specificity on complex research tasks.

2. Why This Particular Approach Was Used (Architectural Rationale)

2.1 Multi-Agent Task Decomposition vs. Monolithic Prompts

When a single prompt is instructed to read multiple papers, summarize them, detect contradictions, uncover gaps, and design experiments, it suffers from the well-documented "Lost in the Middle" phenomenon. By enforcing the Single Responsibility Principle (SRP), ReAssist assigns specialized agents to isolated analytical dimensions: Search, Summarization, Cross-Paper Synthesis, Gap Finding, Idea Generation, Alternative Techniques, and Engineering Guidance.

2.2 LangGraph Declarative State Machine vs. Imperative Scripts

Early versions of the codebase relied on imperative Python scripts with manual retry loops and nested conditionals. ReAssist refactored this into a LangGraph-backed declarative state machine (graph_builder.py):

  • Typed Pipeline State: All nodes share a unified PipelineState typed dictionary, ensuring consistent schemas.
  • Native Self-Healing Loops: Enables cyclic loops, such as query rewriting loops when paper relevance is sub-threshold.
  • Isolated State Diffs: Nodes return partial dictionary updates rather than mutating global memory.
  • Conditional Edge Routers: Deterministic routing between paper grading, rewrites, web fallbacks, and synthesis.

2.3 Context Slicing (required_inputs)

Passing cumulative state between 7 cascading agents produces quadratic $O(N^2)$ token explosion. ReAssist enforces Context Slicing: each agent receives only the exact keys listed in its required_inputs attribute. For example, GapFinderAgent receives only the synthesized text; IdeaGeneratorAgent receives only synthesis and gaps. This slashed cumulative pipeline tokens by 52%.

2.4 Dynamic Model Tiering (Tier 1, Tier 2, Tier 3)

Rather than routing every request to expensive frontier models, ReAssist implements a 3-tier model strategy:

  • Tier 1 (Fast & Classifier): gpt-4o-mini / Claude Haiku / local Phi-3 for binary grading, query rewriting, and verification.
  • Tier 2 (Balanced Execution): gpt-4o-mini / Claude Sonnet for paper summarization and implementation roadmaps.
  • Tier 3 (Frontier Reasoning): gpt-4o / Claude 3.5 Sonnet exclusively for cross-paper literature synthesis, gap deduction, and hypothesis formulation.

2.5 AgenticOps Heuristic Router

Running an 11-agent graph for simple lookups (e.g., "What is Adam optimizer?") is economically wasteful. The AgenticOps Router evaluates incoming queries across 6 lexical markers in under 5ms (without LLM calls). Queries scoring ≤ 4 are routed to a single-prompt CoT baseline, reducing average query costs by ~75%.

4. Technical Obstacles Encountered & Solutions Implemented

Obstacle Faced Root Cause & Impact Engineering Solution Implemented
1. Hallucination Cascades In sequential chains, an ungrounded claim from an early agent is accepted as ground truth downstream, compounding errors. Engineered the AnswerVerifier agent at graph completion. Operates at temperature=0.0 to audit claims against source papers.
2. Retrieval Drift Raw arXiv searches often returned irrelevant papers for dense queries, polluting downstream synthesis. Implemented Corrective RAG (CRAG): RelevanceGrader filters irrelevant papers; QueryRewriter rewrites queries; triggers web fallback if needed.
3. Token Bloat Accumulating raw text and intermediate outputs caused quadratic token growth and prompt truncation. Enforced Context Slicing via required_inputs, capped summarizer chunks at 2000 tokens, and deployed 3-tier model dispatch.
4. Client HTTP Timeouts A 35-second multi-agent pipeline execution exceeded browser HTTP connection and proxy timeout thresholds. Architected an asynchronous job queue in FastAPI (/analyze returns job_id), with client polling and SQLite WAL persistence.
5. Cloud API Lock-in Relying exclusively on proprietary cloud APIs created high costs and vendor vulnerability. Engineered a unified provider abstraction supporting OpenAI, AWS Bedrock, local Ollama (Llama 3.1 / Phi-3), and Hugging Face.

5. End-to-End Operational Workflow

The ReAssist pipeline executes through 12 deterministic stages:

  1. User Ingestion & Job Creation: User submits research query or PDF via Next.js; FastAPI registers background task.
  2. AgenticOps Heuristic Scoring: Fast lexical analysis evaluates complexity and precision. Routes to CoT if score ≤ 4; triggers Multi-Agent if ≥ 5.
  3. Academic Literature Discovery: SearchAgent queries arXiv and Semantic Scholar. In PDF mode, RAGRetrieverAgent extracts vector chunks from ChromaDB.
  4. Binary Relevance Grading: RelevanceGrader classifies paper abstracts as relevant or irrelevant against user intent.
  5. Self-Corrective Query Rewriting: If verified papers < 2, QueryRewriter rewrites the search query and retries (max 2 rewrites). If still failing, triggers Tavily web search fallback.
  6. Chunked Literature Summarization: SummarizerAgent summarizes verified papers in 2,000-token blocks, extracting methods and empirical metrics.
  7. Cross-Paper Knowledge Synthesis: SynthesizerAgent clusters shared paradigms, conflicting findings, and historical progress.
  8. Research Gap Identification: GapFinderAgent isolates open frontiers, unexplored parameter spaces, and benchmark voids.
  9. Novel Idea Generation: IdeaGeneratorAgent outputs formal hypotheses, mathematical formulation, and experimental procedures.
  10. Technique & Framework Mapping: TechniqueAgent specifies baseline models, evaluation metrics, and open-source datasets.
  11. Implementation Guidance: GuidanceAgent estimates difficulty, prerequisite skills, compute requirements, and milestone timelines.
  12. Faithfulness Verification & Presentation: AnswerVerifier audits synthesis against source papers; results are saved to database and rendered in Next.js UI.

6. Deep Dive into Core Technologies

6.1 Vector RAG (Retrieval-Augmented Generation) Architecture

  • Document Processing (document_processor.py): Uses RecursiveCharacterTextSplitter with chunk_size=1000 and chunk_overlap=150, ensuring semantic continuity across chunk edges.
  • Embeddings Abstraction (embeddings.py): Pluggable embeddings supporting OpenAI text-embedding-ada-002, AWS Bedrock Amazon Titan v2, local Ollama nomic-embed-text, and Hugging Face BAAI/bge-large-en-v1.5.
  • ChromaDB Vector Store (retriever.py): Uses persistent HNSW indexing with Cosine distance. Workspaces have isolated collections (ws_{workspace_id}).
  • Corrective RAG (CRAG): Dynamically grades retrieved chunks and triggers query rewrites or web search fallback if vector similarity is weak.

6.2 LangGraph Orchestration Engine

The pipeline is modeled as a compiled LangGraph StateGraph. State mutations are typed via PipelineState. Conditional edge functions (grade_router, rewrite_router, web_search_router) manage non-linear branch execution without imperative spaghetti code.

6.3 Backend & Frontend Engineering

  • FastAPI Backend: Async job dispatch, SQLite with Write-Ahead Logging (WAL) for concurrent writes, and modular REST routers (/auth, /workspaces, /pipeline, /documents).
  • Next.js 15 Frontend: TypeScript, TailwindCSS, custom cyber/glassmorphism design tokens, interactive Markdown rendering, and tabs for Discovery, Concept Generation (Ideation), and Sandboxes.

7. Project Defense & Viva Voce Q&A Cheat Sheet

Q1: Why not just use ChatGPT or Claude directly with a single prompt?
A: Monolithic prompts suffer from attention dilution ("Lost in the Middle") when ingesting multiple papers. They produce vague, generic summaries. By decomposing the workflow into 7 focused agents, ReAssist achieves +56% higher specificity in hypotheses and +112% higher actionability in implementation roadmaps.
Q2: Multi-agent systems are slow and expensive. How do you justify this in production?
A: That is why we built the AgenticOps Router. We do not run the multi-agent pipeline for every query. Simple queries are automatically routed to a single-prompt CoT baseline (9s, $0.0015). The multi-agent pipeline is reserved for complex, novel queries, delivering an overall 75% cost reduction.
Q3: How do you prevent hallucination propagation across cascading agents?
A: We apply two independent guardrails: (1) RelevanceGrader filters out irrelevant papers before synthesis begins, and (2) AnswerVerifier audits the final synthesis against source abstracts at temperature=0.0, explicitly flagging unbacked claims.
Q4: Why LangGraph instead of open-ended frameworks like AutoGen or CrewAI?
A: AutoGen and CrewAI rely on conversational agent loops that are non-deterministic, hard to debug, and token-expensive. LangGraph provides a declarative, typed state machine where state transitions, conditional loops (CRAG), and error recovery are strictly defined and auditable.
